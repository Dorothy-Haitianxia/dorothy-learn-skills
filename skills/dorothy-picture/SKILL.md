# 教学制图

给一份数学或课本材料产出**有教学任务的矢量图**：每个重要知识点都要过一遍评估，每张出图都要写明它解决什么理解问题，位置提前规划，生成后渲染成 PNG 亲眼核对，再交付。

**你不是绘图工具，是制图编辑。** 画得好看不算完成；答不出「这张图帮助读者理解什么」就不该存在。

## 一、输入与输出

你是 dorothy-html 的**制图环节**（也可单独用于别的教学材料）。DSh 没有「skill 调用 skill」的 API，靠两条通道对接：

| 通道 | 约定 |
|---|---|
| 规范通道 | dorothy-html 在生成流程里读本文件，按本文件做制图；它只负责把产出的 figure 片段插到锚点 |
| 脚本通道 | `scripts/check_plan.py`、`scripts/check_figure.py` 双方都能跑；`scripts/render_fig.js` 出核对图 |

### 输入

| 输入 | 说明 |
|---|---|
| 知识点清单 | 该章的定义 / 定理（条件·结论）/ 证明关键步骤 / 例题 / 易错点 / 依赖关系，带卡片 id |
| 正文锚点 | 每个知识点对应正文哪张卡、哪个面板、第几段或哪条公式（写「插入锚点」用） |
| 宿主页令牌 | 颜色令牌名、字体栈、插图标定尺寸；默认取 dorothy-html 的 `reference/design-spec.md`。单独使用时自带一份 |
| `<产物>_figure-assets.md` | **本章可用的本地已有图清单**（路径 / 尺寸 / 能讲什么），由 dorothy-html 提供；没有就写「无」 |

### 输出（三份，都落盘）

| 产物 | 形态 | 谁用 |
|---|---|---|
| `<产物>_figures-plan.md` | **制图规划清单**：打分 + 结论 + 八字段 + 图示规格 + 三层验收，全部并入这一个文件 | 人审 + `check_plan.py` |
| `figs/fig-<N>-<slug>.html` | **完整 `<figure class="fig">` 片段**：内联 SVG + 图例 + 图注 | dorothy-html 直接插到锚点 |
| `<产物>_figures-cost.md` | **成本账**：逐图记可复核的原始量，见第九节 | 人审 |

**来源决策只在这里发生**：本地图库 / 生成图 / 占位三种来源的取舍写在规划清单里（默认优先级：本地已有图库 > 生成图 > 占位图）。**文件搬运**（base64 内联、等比缩放、加主题边框、写 alt）归 dorothy-html。

## 二、强制流程（八阶段，不许跳步）

```
1 提取知识点 → 2 识别理解障碍 → 3 打分 → 4 六问闸门 + 八字段
  → 5 图示规格 → 6 规格检查 → 7 实现（选技术）→ 8 三层验收
```

| 阶段 | 做什么 | 产物落在哪 | 关卡 |
|---|---|---|---|
| **1 提取知识点** | 概念、定义、定理、证明、例题、易混点、知识关联 | 清单的汇总表 | 六类内容源一条不漏 |
| **2 识别理解障碍** | 明确读者可能在哪里误解、卡住、无法继续推理 | 汇总表「依据」列 | 写不出具体位置 → 回到 1 |
| **3 打分** | 结构 / 过程 / 直观 / 辨析 四维 0–2（`reference/assessment.md`） | 汇总表「打分」列 | 任一维 = 2 或总分 ≥ 4 → 必评并优先制图 |
| **4 六问闸门 + 八字段** | 逐条回答六问；答全了再写八字段 | 出图条目 | **六问答不全 → 不制图** |
| **5 图示规格** | 数学对象与符号 / 关系 / 阅读顺序 / **标识职责表** / 与正文术语对应 / **不能暗示的错误结论** | 出图条目的规格块 | 先定义数学语义，再设计布局 |
| **6 规格检查** | 规格是否自洽：每个标识都有职责？有没有暗示错误结论？ | — | 不合格 → 回 5 |
| **7 实现** | 选技术（默认令牌化内联 SVG；对照与分步可用 HTML 结构），用 `scripts/lib/figlib.py` 生成 | `figs/*.html` | 图内不写颜色字面量 |
| **8 三层验收**（动态图再加一层「运行时」） | 数学正确性 / 视觉表达 / 教学有效性，**分开记录**；动态图的运行时层只能人工点一遍 | 出图条目的验收块 | **不合格不得靠加颜色箭头修补，只能重画** |

**禁止「先写完 HTML，再随手补图」。没有具体锚点之前不许开始画。**

## 三、硬要求

### 1. 所有重要知识点都要过评估，但重要 ≠ 必须配图

逐类检查，每类都要给出结论：

| 内容源 | 评估重点 |
|---|---|
| 核心概念及其定义 | 定义里的对象、条件、映射关系能否变成可见结构 |
| 定理的条件、结论及其相互关系 | 条件到结论的蕴含方向、条件缺一不可之处 |
| 证明中的关键推理步骤 | 哪一步是转折、用了什么工具、为什么此处能用 |
| 例题中的构造、计算和转折 | 构造动作、计算路径、关键转折点 |
| 容易混淆的概念、边界条件和反例 | 相似概念差在哪、边界条件被破坏时会发生什么 |
| 多个知识点之间的依赖关系 | 本章在整段知识里的位置、谁依赖谁 |

**凡存在合理可视化可能的，优先尝试设计解释性图**；确实不值得画的，用替身手段并在清单里写明（编号回指 / 术语表 + 解剖图 / 排版公式 / 缺失的连接 / 纯文字对比）。

### 2. 每张图必须解决一个具体的理解问题

六问闸门：① 读者**具体**在哪卡住 ② 图要让读者看见**什么关系** ③ 为什么图比文字 / 公式 / 表格合适 ④ **删掉它读者会失去什么** ⑤ 看完能解释什么 ⑥ **不能暗示什么错误结论**。

**第 4 问是反装饰的闸门，第 6 问是反误导的闸门。** 答不出「会失去什么」的图一律删掉。

### 3. 先明确类型，再选图型

五类：**结构关系图 / 几何直觉图 / 证明流程图 / 对照反例图 / 数据分布图**。类型由「这张图要消解哪一维困难」决定：

- 结构维度 → 结构关系图；直观维度 → 几何直觉图；过程维度 → 证明流程图或分步的结构图；辨析维度 → 对照反例图。
- **数据分布图只在材料本身给的就是分布 / 计数 / 逼近时使用**，不要用它去画结构或几何。

### 4. 位置必须提前规划，而且要**紧邻**

**空间邻近原则**：图要放在**首次引用它的那句话之后**，不是「放在同一节」。读者不该为了理解一个箭头来回翻找它对应的定义。

- **绝不在定义 / 定理陈述之前预告**（唯一例外：预览图 + 免责说明）；
- **不做章节末尾总结图**；
- 图前铺垫 **1–3 句**，图后解释 **1–4 句**，图后任务句平均**每 8 张至少 1 次**；
- 锚点必须落到具体段落 / 公式 / 步骤 / 面板，**不许用「适当位置」交差**。

### 5. 信号原则：标识要指向读者此刻该注意的关系

关键不是增加多少颜色、编号或箭头，而是它们**有没有指向读者此刻应该注意的关系**。

- 每个标识都要在**标识职责表**里填出「此刻指向哪个关系」；填不出来的删掉；
- 颜色不能是唯一载体（还要靠线型 / 形状 / 填充样式 / 编号）；
- 同一标识在同一份交付里含义必须一致；标识迁移本身若是要讲的内容，要在正文逐句说明。

### 6. 数学内容的特殊要求

- **不允许以示意图替代证明**：图可以建立直觉、解释结构、索引推理，但不能把未经证明的图形直觉当严格论证；服务证明步骤的图，首要任务只能写「让这一步用了什么工具变得可见」。
- **关键公式必须解释作用**：说明对象各表示什么、这一步用了什么条件或工具、解决了什么问题；有对应图时指明公式哪部分对应图中哪个标识。
- **条件必须显式呈现**：定理依赖的条件要标出来；反例要指出它保留了哪些性质、破坏了哪项条件。
- **区分事实 / 直觉 / 示意**，并在图注里标出；示意图不得暗示比原定理更强的结论。
- **不得从有限个例子推出一般结论**；材料不足时说明缺什么，不编造。

### 7. 图文必须形成教学闭环

**图前引导（1–3 句）→ 核心图片 → 图中引导 → 图后解释（1–4 句）→ 理解检查**。

不写「如图所示」就完事，也不认为插了图就完成了讲解。**图后问题检验不了这张图想传达的内容，就重新设计图或问题。**

## 四、图型库（`scripts/lib/figlib.py`）

制图前先查 **`reference/selection-samples.md`**（四章 80 张实测教材图的选型样本集）：按教学任务找到最接近的样本，看它的做法与证据。其中最重要的一条是**同尺度并置**——多个变体 / 正反例 / 左右对照并排时，各面板的节点坐标必须完全相同，只变高亮或映射。

| 类型 | 图型入口 | 用途 |
|---|---|---|
| **结构关系图** | `objmap()` | 左右两列对象框 + 带关系名的箭头（对象与映射） |
| | `depgraph()` | 分层节点 + 有向边（知识依赖、局部地图） |
| | `stages()` | 横向阶段框 + 箭头 + 编号（流程、分步构造） |
| **几何直觉图** | `gcircle()` `garc()` `gchord()` `gpoly()` `ghline()` `gpt()` | 圆 / 弧 / 弦 / 正多边形 / 等距弦 —— 几何构件 |
| | `chord_models()` | 参考实现：同一条弦、三种「随机」→ 三个几何区域 |
| **证明流程图** | `proof()` | 编号步骤 + 每步依据 + 依赖箭头 |
| **对照反例图** | `compare()` | 左右同构两栏 + 差异行强调 |
| | `axis()` | 数轴 + 区间带 + 标注点（阈值事件、邻域、覆盖） |
| **数据分布图** | `poisson_bars()` `memoryless_line()` `bertrand_area()` | 三个参考实现（柱 / 折线 / 面积）；**改数据即可复用**，但只在材料本身是分布时使用 |
| **交互图（动态）** | 内联 SVG + 内联 `<script>` | 内容随参数变化 / 随机 / 可迭代 / 可穷举时用它；静态首帧必须自立，JS 只加料。见 `reference/interactive.md` |

#### 交互图（HTML 相对 PDF 的优势）

内容本身**随参数变化、随机、可迭代、可穷举**时，把它做成动态图：内联 SVG + 内联脚本，**静态首帧必须自立**（`render_fig.js` 只能渲首帧，打印 / 无脚本 / 读屏都要能读）。

六种手法（抽样迭代 / 参数滑块 / 分步揭示 / 拖拽对象 / 联动高亮 / 状态切换）、四条硬约束（内联 SVG 主体、无外链字面量、只动 opacity 与 transform、控件用 `fig__ctl`）与**运行时验收**见 **`reference/interactive.md`**。

#### 命名规范

- **图型函数用形态名**（`objmap` / `axis` / `compare` …），不带前缀；
- **具体实例用「内容_形态」**（`bertrand_area` / `poisson_bars` / `chord_models`）；
- **不要沿用外部图库的编号体系**（旧的 `B1/B2/B3` 与 `fig_*` 前缀已废弃）。

#### 复杂度上限（实测自两本教材）

**常规图 ≤ 14 个对象、≤ 8 个关系**（Visual Group Theory 第 2 章实测为 12 / 4；复分析第 1 章为 14 / 8）。

超过上限的五种处理：拆多面板（每面板只引入 1 个新关系）／拆跨图号连续图（每步只增 1 个对象 + 1–2 个关系）／局部放大／改用表格或纯公式／打包为「预览」+ 免责说明。**不许缩小字号硬塞。**

#### 数据来源纪律

数据必须来自材料的公式；**示意参数要写在图注里**（例：「图中取 λ = 1 示意」）；发散、截断、近似都要标出来。**不许自造数据。**

## 五、视觉硬约束

**图内不写颜色字面量、不写 `stroke=` / `fill=` 属性**：只挂语义类，颜色由宿主页样式表按令牌给。这样风格与页面**同源**，并顺带跟随主题切换 —— 零成本副产品。

| 类别 | 类名 | 用途 |
|---|---|---|
| 线 | `f-grid` `f-axis` `f-rail` `f-hair` `f-hair--acc` `f-hair-thin` `f-rung` `f-line` `f-line--acc` `f-line--acc-dash` `f-rule-dash` `f-rule-dash-sm` `f-bracket` | 网格 / 轴 / 轨道 / 发丝 / 主折线 / 参考虚线 / 括号 |
| 结构 | `f-box` `f-box--acc` `f-band` `f-link` | 对象框 / 强调框 / 区域带 / 结构连线 |
| 点 | `f-dot` `f-dot--acc` `f-dot-hollow` `f-tick` `f-arrow` | 确定点 / 强调点 / 空心点 / 刻度 / 箭头 |
| 文字 | `t-num`（数值，加粗 + 光晕）`t-lab`（标签）`t-note`（全大写等宽注记） | 数值 / 标签 / 注记行 |
| 入场 | `f-fade` 及 `.panel.is-in .fig …` 的 `figFade` / `figDraw` / `figPop` | 卡片展开时才播；`prefers-reduced-motion` 下落终态 |

- 图内字号 ≥ 11px；注记走等宽，正文标签走 `--font-text`；
- **需要新语义时先在 `design-spec.md` 登记样式**（基础 `:root` 一条 + NASA-punk 一条），再使用；
- 图形元素用 `role="img"` + `aria-label`（非空、不以「图片 / 示意图」开头）并带 `<title>`；图注格式见 `reference/plan-contract.md` 第五节。

```powershell
$sk = "$HOME\.agents\skills\dorothy-picture"   # 或工作区源码 skills\dorothy-picture
# 1) 规划清单自检（打分 / 六问 / 八字段 / 规格 / 三层验收 / 锚点可定位）

& '<node>' --check '.work\_figjs.js'
# 5) 图要离开宿主页时，导出固化色值的一版
node "$sk\scripts\render_fig.js" --figure 'figs\fig-1-xxx.html' --css '<样式源>' --out '.work\fig-1.svg' --bake
```

## 九、成本账（`<产物>_figures-cost.md`）

每章都要记，**逐图一行**，只记可复核的原始量：

| 列 | 怎么取 |
|---|---|
| 图号 / 文件名 | `fig-<N>-<slug>` |
| 类型 / 图型 | 第四节里的类型与入口名 |
| 生成器 | 生成这张图的代码行数 / 字符数 |
| SVG 体积 | 产出片段的字节数 |
| 核对轮次 | 渲染 — 看 — 改 的循环次数（第一次渲染算 1 轮） |
| 返工 | 因几何 / 文字 / 重叠问题重画的次数 |
| 来源 | 生成 / 本地图库（文件名）/ 占位 |

末尾给**来源方案对照**（本地位图内联 vs 矢量化生成）与**口径说明**：本机拿不到 harness 的精确 token 计数，所以用可复核的原始量作代理，并注明换算口径。
