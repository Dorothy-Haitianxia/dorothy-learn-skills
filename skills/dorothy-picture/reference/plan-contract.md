# 图件契约：七问闸门 + 决策卡 + 编排 + 三层验收

本文件规定一张图在**动手之前**必须写全的东西、**凭什么落在正确的位置**、**按什么节奏交代给读者**，以及**验收要分开记什么**。

字段名以脚本为准：`python scripts/check_plan.py --fields` 打印的就是校验器实际认的名字。改本文件必须同步改 `scripts/check_plan.py` 的 `REQUIRED` / `OPTIONAL`。

---

## 一、七问闸门（答不全就不制图）

逐条回答，写不出答案的那条就是「不画」的理由。

| # | 问题 | 答不出来的后果 |
|---|---|---|
| 1 | 读者**具体**会在哪里遇到困难？ | 还没定位障碍 → 回到第一步 |
| 2 | 图需要让读者看见**什么关系或变化**？ | 图没有任务 → 不画 |
| 3 | **为什么图比纯文字、公式或对照表更合适？** | 表达方式选错了 → 改用表格 / 公式 / 编号回指 |
| 4 | **如果删除这张图，读者会失去什么？** | 答不出会失去什么 → **这张图是装饰，删掉** |
| 5 | 读者看完图后应当能**解释什么**？ | 无法验收 → 先定验收问题 |
| 6 | 这张图**不能暗示哪些错误结论**？ | 有误导风险 → 不画，或先在图上堵住 |
| 7 | **如果不画这张图，最好的替代文本是什么？——必须真的写出来。** | 写不出可用的替代 → 说明图还没想清楚；只答「没有替代」= 不合格 |

第 4 问拦装饰，第 6 问拦误导，第 7 问拦「想不清楚所以画一张糊过去」。

第 7 问的答案落到决策卡的 `替代文本` 字段。它有两个用处：写不出来时直接改用替代方案；写出来后做图注与 alt 的底稿。

## 二、决策卡（11 个必需字段）

每一项都要写得能让别人照着做。括号里是「不合格写法」的典型。

| 字段 | 写什么 | 不合格 |
|---|---|---|
| **对应知识点** | 卡片 id + 名称（如 `c3 分布（律）`）；只服务证明的一步就写「`t7` 证明第 3 步」 | 「关于分布的那块」 |
| **打分** | 四维分数 + 总分 + **依据**（见 `assessment.md` 第二节） | 只填数字不写依据 |
| **理解障碍** | 一句话：读者在哪一步、会**怎么想错**。可加一类标签（符号陌生 / 缺动机 / 跳步 / 混淆 / 抽象无锚点 / 只会算不会用） | 「理解不深」「不够直观」 |
| **教学任务** | 单句 + 图型入口（如「让…可见 —— 结构关系 / objmap()」）。一个任务，不并列 | 写三个任务并列 |
| **插入位置** | 锚点 + **位置理由**。格式：`c3-body · 第 1 段之后 —— 理由：读者刚读完定义、正卡在「为什么还要造新测度」` | 「适当位置」；只有锚点没有理由 |
| **编排** | 三默认之一或五例外之一（见第四节），例外必须写理由 | 只写「放在图后」 |
| **视觉顺序** | 先看什么 → 再比较什么 → 最后得出什么。≥3 个需顺序阅读的元素必须有编号或方向箭头 | 「从左到右」 |
| **图文对应** | 逐条写「图中元素 ↔ 哪句正文 / 哪条公式 / 哪一步推理」 | 「正文已有说明」 |
| **图后解释** | 正文在图之后写什么：结论或缺口（1–4 句）+ 一句下一步指令。**这是要落到 HTML 里的文字** | 「略」「见图」 |
| **理解检查** | 看完图后读者应能回答的**一个**问题，**必须带「（答案：…）」** | 「是否理解了」；只有问题没有答案 |
| **替代文本** | 第 7 问的答案：不画的话用什么替代、它为什么不够 | 「无」「不适用」「没有替代」 |

**关键元素已并入 `视觉顺序`**：顺序句里必然点名元素，再单列一份元素清单只会重复。若元素超过 7 项，先问能不能拆图。

## 三、条件字段（触发才填）

| 字段 | 触发条件 | 写什么 |
|---|---|---|
| **标识职责** | 图里用了箭头 / 编号 / 高亮 / 颜色 / 虚线 / 分阶段揭示 | 每个标识「此刻指向哪个关系」；写不出职责的标识一律删 |
| **不能暗示的错误结论** | 图容易被误读（对照图、示意参数、截断曲线、有限样本） | 这张图最容易被读成什么错话？在图注或元素上堵住 |
| **图前引导** | 图需要铺垫（默认需要） | 1–3 句：提出读者此刻的问题 + 读图约定 |
| **图后任务句** | 连续 8 张图里至少 1 次 | 让读者动手：自己验证一步 / 找一个反例 / 预测下一格 |
| **失败原因** | 有理解检查时 | 读者答错时的常见原因（用来反查图是否误导） |

标识职责的最小形态：

```
| 标识 | 形态 | 此刻指向 |
| 橙色实线 | 长弦 | 「弦长 > √3R」的样本，读者要比较它与虚线弦 |
| 虚线 | 临界弦（长 = √3R） | 阈值本身，不是操作 |
| 橙色弧 | 允许的端点区域 | 分母（弧长占比） |
```

## 四、编排策略（3 种默认 + 5 种例外）

编排回答的是「图与解释按什么节奏交给读者」，不是「图画什么」。

### 默认三选一（按图型直接对应）

| 图型 | 默认编排 | 做法 |
|---|---|---|
| 结构关系 / 依赖 / 对照 | **并置** | 图与解释同屏，图在前、解释紧跟；读者不需要记住前文就能读图 |
| 过程阶段 / 证明步骤 | **分阶段揭示** | 静态版用编号 + 逐步高亮；交互版用按钮。一次只让一个阶段成为焦点 |
| 易混概念 / 反例 | **并列对照** | 同尺度、同坐标、只变一处；差异必须落在同一位置，不能靠读者自己找 |

### 例外五选一（用必须写理由）

| 例外 | 什么时候用 | 风险 |
|---|---|---|
| **先概览后细节** | 整章 / 整节的结构图，读者需要一个位置感 | 细节图必须紧跟，否则概览变成孤图 |
| **先提问再给图** | 读者有先验误解、需要先暴露出来 | 问题必须可判定对错，不能是「你觉得呢」 |
| **先预测再揭示** | 反直觉结论（无记忆性、Bertrand、边缘不决定联合） | 预测必须有记录方式，否则读者滑过去 |
| **后置总结图** | 前面已经逐个讲过、需要一次收束 | 与「不做章末总结图」冲突；只在节内、且必须引用前文具体位置时可用 |
| **局部放大** | 关键差异在整体尺度上看不见（无穷小、临界点、截断） | 放大区必须标出它在整体的位置 |

**不要把编排写成绝对规则**：先验知识、任务难度、图的复杂度、阅读顺序、移动端布局都会改变最优选择。写清适用任务、风险、验证方法即可。

## 五、插入锚点与位置理由

锚点必须能被机械定位：

| 形式 | 例子 | 说明 |
|---|---|---|
| 卡片 + 面板 + 段序 | `c3-body · 第 2 段之后` | 最常用；段序从 `.panel__inner` 的第 1 个子元素算起 |
| 卡片 + 公式 | `c3-body · 公式「ℙ_X := ℙ ∘ X⁻¹」之前` | 用公式的**可辨识片段**定位 |
| 卡片 + 步骤 | `t7-body · 证明第 3 步之后` | 服务特定证明步骤的图 |
| 卡片 + 面板 | `e2-body · 面板 b 之后` | 多面板图的面板级引用 |

**位置理由**是不可省略的一半：为什么是这一段而不是上一段？典型合格理由：

- 读者刚读完 X、正卡在「那为什么还需要 Y」；
- 这句话首次引用了图中元素；
- 这是推理链的转折步，下一步要用到图里标出的关系。

校验器会检查卡片 id 与公式片段是否真的存在于产出 HTML 里。

## 六、位置与篇幅（两本教材实测规律）

### 位置

1. **图必须紧邻它解释的正文**（空间邻近原则）——不是「放在同一节」，而是**放在首次引用它的那句话之后**。
2. **绝不在定义 / 定理陈述之前预告**：实测两本书 44 张图，没有一张出现在它所指内容之前。唯一例外：预览图，但必须配免责说明。
3. **不做章节末尾总结图**：44 张图里一张都没有。
4. 服务证明步骤的图放在**该步骤附近**；对照图放在两个概念都出现之后。
5. 一个段落区间内不超过 1 张图；一张卡片不超过 2 张图。

### 篇幅（可量化）

| 位置 | 实测篇幅 | 写什么 |
|---|---|---|
| 图前铺垫 | **1–3 句** | 1 句预告（提出读者此刻的问题）+ 0–1 句读图约定 |
| 图后解释 | **1–4 句** | 结论或缺口 + 1 句下一步指令 |
| 图后任务句 | 平均**每 8 张至少 1 次** | 让读者动手 |

固定模式：**预告句 → 读图约定句 → 图 → 结论 / 缺口句 → 下一步指令句**。

## 七、图注体例（二选一，全页一致）

| 体例 | 图注写什么 | 解释权 | 适用 |
|---|---|---|---|
| **说明式**（本 skill 默认） | `图 N · 一句话说明（正文 §X.Y）` | 图注给一句话，正文展开 | 图文并重的知识笔记 |
| **编号式** | 只有 `图 N` | 解释权全部归正文 | 正文本身很密、图很多时 |

两种都要：**数据来源、示意参数、发散 / 截断写进图注**（如「图中取 λ = 1 示意」）。

## 八、状态字段

| 状态 | 含义 |
|---|---|
| `未开始` | 已规划，还没生成 |
| `已生成` | 片段落盘，**还没渲染核对** |
| `已渲染核对` | 渲染成 PNG 亲眼看过，三层验收已记录 |
| `已内联` | dorothy-html 已插进 HTML |
| `已弃用` | 曾规划或曾生成，后决定不用；**必须写理由** |

**只有 `已渲染核对` 之后才能进 `已内联`。** 状态是 `已生成` 的图不许交付。

## 九、三层验收（分开记，不许合并）

| 层 | 查什么 | 记录要求 | 判定方式 |
|---|---|---|---|
| **第一层 · 数学正确性** | 对象、关系、条件、量词、论证方向是否准确；图注数值是否与材料一致 | 逐条写「查了什么、结论是什么」 | 人工对照 + `check_figure.py` |
| **第二层 · 视觉表达** | 阅读顺序、标签、箭头、颜色（是否为唯一载体）、布局、重叠、缩放后的可读性 | 由 `render_fig.js` 渲图 + 亲眼看 | 人工对照（必须真的打开 PNG） |
| **第三层 · 教学有效性** | 是否解决了预设的理解障碍？读者能否用图回答理解检查？是否引入新的误解？ | 回答要有判断，不能复述图注 | 人工对照 |

**禁止用「清晰」「美观」「直观」「更易懂」作为通过依据。** 每层都要写具体条目。

不合格的图**不得仅通过增加颜色、箭头或装饰来修补**——只能重画或改设计。
