# 图件契约：八字段 + 图示规格 + 三层验收

本文件规定一张图在**动手之前**必须写全的东西、**凭什么落在正确的位置**，以及**验收要分开记什么**。

## 一、八字段（配图决策卡）

每一项都要写得能让别人照着做。括号里是「不合格写法」的典型。

| 字段 | 写什么 | 不合格 |
|---|---|---|
| **对应知识点** | 卡片 id + 名称（如 `c3 分布（律）`）；只服务证明的一步就写「`t7` 证明第 3 步」 | 「关于分布的那块」 |
| **打分** | 四维分数 + 总分 + 依据（见 `assessment.md` 第二节） | 只填数字不写依据 |
| **插入锚点** | 见第三节，必须可机械定位，且落到段落或面板 | 「适当位置」 |
| **前置问题** | 读者看图**之前**应该正在想的问题，一句问句 | 「帮助理解定义」 |
| **首要教学任务** | 单句，从 `assessment.md` 第五节那几类里选一个 | 写三个任务并列 |
| **关键元素** | 图里必须出现的对象、符号、区域、箭头、编号、注释（逐项列） | 「画出主要关系」 |
| **图后解释** | 正文如何把图中元素逐一对应回数学内容（哪个元素 ↔ 哪条定义 / 公式） | 「正文已有说明」 |
| **理解检查** | 看完图后读者应能回答的**一个**问题（能检验这张图想传达的内容） | 「是否理解了」 |
| **图型与障碍类型** | 类型（结构 / 几何 / 证明 / 对照 / 数据）+ 图型入口名（如 `A 对象与结构 / objmap()`） | 只写「结构图」不写入口 |

## 二、图示规格（并入清单，不单独落盘）

**先定义数学语义，再设计视觉布局。** 每张图在写代码之前，把下面七条补在八字段之后：

| 规格项 | 写什么 |
|---|---|
| **数学对象与符号** | 图里每个对象在正文里叫什么、用什么符号；**图中符号必须与正文、公式、图例完全一致** |
| **对象之间的关系** | 包含 / 映射 / 变换 / 逼近 / 分类 / 依赖，逐条列出 |
| **阅读顺序** | 从左到右 / 从上到下 / 中心向外 / 按编号；≥3 个需按序阅读的元素必须有编号或方向箭头 |
| **标识职责表** | 每个颜色、编号、箭头、虚线、阴影**此刻指向哪个关系**；写不出职责的标识一律删（信号原则） |
| **与正文术语的对应** | 正文哪一句点名了图中哪个元素 |
| **不能暗示的错误结论** | 这张图容易被误读成什么？在图注或元素上堵住（六问第 6 问） |
| **图后检查问题** | 与「理解检查」一致，链到正文那一段 |

标识职责表的最小形态：

```
| 标识 | 形态 | 此刻指向 |
| 橙色实线 | 长弦 | 「弦长 > √3R」的样本，读者要比较它与虚线弦 |
| 虚线 | 临界弦（长 = √3R） | 阈值本身，不是操作 |
| 橙色弧 | 允许的端点区域 | 分母（弧长占比） |
```

## 三、插入锚点

锚点必须能被机械定位。允许的形式：

| 形式 | 例子 | 说明 |
|---|---|---|
| 卡片 + 面板 + 段序 | `c3-body · 第 2 段之后` | 最常用；段序从 `.panel__inner` 的第 1 个子元素算起 |
| 卡片 + 公式 | `c3-body · 公式「ℙ_X := ℙ ∘ X⁻¹」之前` | 用公式的**可辨识片段**定位 |
| 卡片 + 步骤 | `t7-body · 证明第 3 步之后` | 服务特定证明步骤的图 |
| 卡片 + 面板 | `e2-body · 面板 b 之后` | 多面板图的面板级引用 |

**锚点必须能在产出 HTML 里找到**（`check_plan.py` 会校验卡片 id 与公式片段是否存在）。

## 四、位置与篇幅（两本教材实测规律）

### 位置

1. **图必须紧邻它解释的正文**（空间邻近原则）——不是「放在同一节」，而是**放在首次引用它的那句话之后**。
2. **绝不在定义 / 定理陈述之前预告**：实测两本书 44 张图，没有一张出现在它所指内容之前。
   唯一例外：**预览图**（如「后面会讲到的谱系」），但必须配免责说明（「你不必现在就完全看懂这张图」）。
3. **不做章节末尾总结图**：44 张图里一张都没有。
4. 服务证明步骤的图放在**该步骤附近**；对照图放在两个概念都出现之后。
5. 一个段落区间内不超过 1 张图；一张卡片不超过 2 张图。

### 篇幅（这是可量化的）

| 位置 | 实测篇幅 | 写什么 |
|---|---|---|
| 图前铺垫 | **1–3 句** | 1 句预告（提出读者此刻的问题）+ 0–1 句读图约定（图例怎么读） |
| 图后解释 | **1–4 句** | 结论或缺口（「图 N 表明…」）+ 1 句下一步指令 |
| 图后任务句 | 平均**每 8 张至少 1 次** | 让读者动手（自己验证 / 画出下一步 / 找一个反例） |

固定模式：**预告句 → 读图约定句 → 图 → 结论 / 缺口句 → 下一步指令句**。

## 五、图注体例（二选一，全页一致）

实测两本教材体制相反，必须**先在清单里声明用哪种**，全页不得混用：

| 体例 | 图注写什么 | 解释权 | 适用 |
|---|---|---|---|
| **说明式**（本 skill 默认） | `图 N · 一句话说明（正文 §X.Y）` | 图注给一句话，正文展开 | 图文并重的知识笔记 |
| **编号式** | 只有 `图 N` | 解释权全部归正文 | 正文本身很密、图很多时 |

两种都要：**数据来源、示意参数、发散 / 截断写进图注**（如「图中取 λ = 1 示意」「p 在 x → 2⁻ 处发散，曲线在 1.915 处出图」）。

## 六、状态字段

| 状态 | 含义 |
|---|---|
| `未开始` | 已规划，还没生成 |
| `已生成` | 片段落盘，**还没渲染核对** |
| `已渲染核对` | 渲染成 PNG 亲眼看过，三层验收已记录 |
| `已内联` | dorothy-html 已插进 HTML |
| `已弃用` | 曾规划或曾生成，后决定不用；**必须写理由** |

**只有 `已渲染核对` 之后才能进 `已内联`。** 状态是 `已生成` 的图不许交付。

## 七、三层验收（分开记，不许合并）

| 层 | 查什么 | 记录要求 |
|---|---|---|
| **第一层 · 数学正确性** | 对象、关系、条件、量词、论证方向是否准确；图注里的数值是否与材料一致 | 逐条写「查了什么、结论是什么」 |
| **第二层 · 视觉表达** | 阅读顺序、标签、箭头、颜色（是否为唯一载体）、布局、重叠、缩放后的可读性 | 由 `render_fig.js` 渲图 + 亲眼看 + `check_figure.py` 给出 |
| **第三层 · 教学有效性** | 是否解决了预设的理解障碍？读者能否用图回答图后问题？是否引入新的误解？ | 回答要有判断，不能复述图注 |

**禁止用「清晰」「美观」「直观」「更易懂」作为通过依据。** 每层都要写具体条目。

不合格的图**不得仅通过增加颜色、箭头或装饰来修补**——只能重画或改设计。
